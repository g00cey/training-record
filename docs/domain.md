# ドメイン用語・分析ロジック・落とし穴

## 用語集

| 用語 | 意味 |
|------|------|
| 自重 / bodyweight | 外部重量なしの種目（懸垂・ディップス・腕立て・自重スクワット等）。`weight` は `null` |
| フリーウェイト / FW | ダンベル系種目（ヒップストラスト・ショルダープレス等） |
| 自重メニュー | 9 種目。毎日実施 |
| FW メニュー | 13 種目。1 日おき（週 3.5 回） |
| スプリットルーティン | 自重（毎日）+ FW（1 日おき）の 2 系統運用。2026-07-30 開始 |
| 記録区分（`notes`） | `自重のみ` / `自重＋フリーウェイト`（`FWのみ` 等の派生あり） |
| Volume Load | `Σ weight × reps × sets`。筋肥大の主指標 |
| RPE | 主観的運動強度（Borg CR-10, 1–10）。心拍計がない時の代替 |
| TRIMP | 有酸素の負荷 = `duration_min × (avg_hr / max_hr_est)`。`max_hr_est` 既定 180 |
| ACWR | 急性(7日) : 慢性(28日平均/週) 負荷比 |
| デロード | 4–6 週に 1 回、ボリュームを 40–50% 落とす回復週 |
| プログレッシブオーバーロード | 漸進的過負荷。増加は週 10% 以内に抑える |
| ルーティン / メニュー / プリセット | `routine_snapshots`。実施予定の種目・重量・回数のテンプレ |

## Volume Load 計算

`training_load_analysis.py` の移植。

- 通常種目: `weight × reps × sets`
- 自重種目: `weight` が `null` の場合、**自重種目リストに含まれるなら `profile.bodyweightKg`** を、含まれないなら `0` を weight とみなす
- 現行の自重種目リスト（`BODYWEIGHT_EXERCISES`）:
  `懸垂` / `懸垂レッグレイズ` / `ディップス` / `バックエクステンション` / `ベンチレッグレイズ`
  - ※ `腕立て伏せ` `自重スクワット` `懸垂（宽握）` は現行リストに**入っていない**（= Volume Load 0 扱い）。
    Web 版で見直すかは要検討（`domain.md` の TODO）。当面は現行踏襲。

## ACWR ゾーン判定（`training_load_analysis.py`）

| ACWR | ゾーン | 対応 |
|------|--------|------|
| 0（データ不足） | `no_data` | 直近 7 日の記録なし |
| < 0.6 | `low` | 効果が薄い可能性 |
| 0.6–0.8 | `slightly_low` | もう少し上げてよい |
| 0.8–1.3 | `safe` | 適切 |
| 1.3–1.5 | `caution` | やや高め。増加は控えめに |
| > 1.5 | `warning` | 怪我リスク高。デロード推奨 |

計算:
- 急性 = 直近 7 日の (筋トレ Volume Load + スピン TRIMP) 合計
- 慢性 = 直近 28 日の同合計 ÷ 4（週平均）
- `acwr = acute / chronic_weekly`

## 故障予防アドバイス（仕様の出典: `SKILL.md`）

Web 版で実装する場合の判定ルール:

- **プログレッシブオーバーロード**: 種目の前回比 増加 ≤10% → OK / >15% → 警告 / 短期連続増 → 警告
- **頻度チェック**（`summary --days 14` 相当）:
  - 筋トレ+スピン 計 7 回以上/2週 → 良好
  - 筋トレ 3 回未満/2週 → 少ない
  - 連続日で間隔 24h 未満 → 休息不足
  - 2 週間完全オフ → 再開は減量スタート
- **要チェック種目**（故障リスク高い順）: ショルダープレス / サイドレイズ → ディップス → スカルクラッシャー → 懸垂 → ダンベルデッドリフト → フロントラックスクワット
- 詳細は `references/exercise-form-guide.md`（全種目フォーム）、`references/split-routine-analysis.md`（筋群別頻度・ボリューム戦略）

優先度は低め（フェーズ 6）。まず記録・表示・グラフを固める。

## 落とし穴（`SKILL.md` Common Pitfalls ＋ Web 化の注意）

1. **同一日付は 1 セッション**。現行 CLI は `INSERT OR REPLACE`（上書き）。API では `POST`=新規(409)/`PUT`=置換/`POST .../exercises`=追記 に分離。UI でも「置換」か「追記」かを明示。
2. **ルーティンと実績は別テーブル・別操作**。record 系にルーティン情報を混ぜない。
3. **自重種目の `weight` は `null`**（`0` ではない）。フォームのデフォルト値・バリデーションに注意。
4. **日本語種目名の表記ゆれ**。`GET /api/exercises` の既存名に寄せる。オートコンプリート必須。将来は種目マスタ化。
5. **キー名**: DB は `routine_snapshots.exercise_name`、API は `name` に統一（境界で変換）。
6. **同名種目の複数エントリ**（「懸垂 10r」「懸垂 6r」）は独立行として保持・表示。1 行にまとめない。
7. **`routine_snapshots` は履歴**。最新 `date` のみが「現在」。部分更新でも新スナップショットを作る設計。
8. **RPE 自動算出**: 未指定 + avg/max HR あり → `round(avg/max*10)` を 1–10 にクランプ。
9. **プロフィール値**（体重 86kg 等）は現行スクリプトにハードコード。Web 版は `profile` テーブル化。Volume Load の結果が体重設定に依存する点に注意。
10. **タイムゾーン**: `Asia/Tokyo` 固定。`date` は文字列。サーバの「今日」判定は JST で行う。
